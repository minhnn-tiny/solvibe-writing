A maintainer receives an agent's patch for an audited Solidity defect. The regression example in the report now passes. What does that result establish for a caller who uses the contract through a different interface? In an archived study of one Angstrom finding, 96 patches passed the example supplied to the repair agent. Eighteen of those patches failed a second security check that was fixed before those patches were assessed. We use this observation to distinguish three questions. Does a patch restore the reported operation while preserving its specified ordinary use? Does it also restore a separately documented behaviour? Would showing the agent a different example change which behaviour it repairs? We report how far public findings support these measurements. Of 160 external findings reviewed for scope, 38 cleared that review, 37 built on both historical revisions, and 18 demonstrated the affected ordinary use offline on both. Historical checks also exposed a grading problem. A patch can silence a failure by disabling the operation. Under our amended rule the scorer must also observe a permitted outcome for that operation. We describe a randomized comparison in which both illustrated behaviours are graded regardless of which example the agent receives. At the reporting cut no case had signed admission and no expanded-benchmark repair session had run. The causal effect of example choice remains open.
